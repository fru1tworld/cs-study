  - 시장은 독립적인 전문 엔진으로 분화하되 공통 질의 인터페이스 등 일부 계층을 공유할 가능성이 큼
- 요지

  - 전문화는 성능을 높이지만 여러 시스템을 연결하는 운영 복잡성을 함께 만듦

  - 실험에서 운영 기능으로 이어지는 수명주기를 같은 병렬 플랫폼에서 지원하면 이동 및 운영 비용을 줄일 수 있음

  - 코드 특수화, 병렬화, 저수준 계산 공유를 결합해 학습 시간을 크게 줄이는 접근을 제시함

  - 레이크는 운영 시스템 간 통신 경로가 아니라 분석과 역사 기록을 위한 기반으로 사용해야 함

  - 시스템 간 데이터 이동과 중복이 현대 아키텍처의 핵심 문제가 됨을 보여줌
- 핵심 내용
  - Reverse ETL은 웨어하우스의 변환된 데이터를 CRM, 광고, 마케팅, 지원 같은 운영 도구로 동기화함
  - source, model, sync, destination으로 구성되며 SQL 모델 결과를 외부 API의 필드에 매핑함
  - 전통적 ETL은 조직이 통제하는 웨어하우스에 쓰지만 Reverse ETL은 서로 다른 제약과 실패 방식의 외부 API에 씀
  - 변경된 레코드만 골라 보내는 diff, 중복 제거, rate limit, 재시도, 오류 관측이 필요함
  - 대상 시스템에는 되돌리기 기능이 없을 수 있어 권한, 승인, 감사 로그, 환경 분리 같은 거버넌스가 중요함
  - 웨어하우스를 단일 정의의 근거로 유지하면서 분석 결과를 일상 업무 도구에서 바로 사용하게 함
- 해석 시 주의
  - Reverse ETL 제품 공급자가 작성한 자료이므로 개념 설명과 제품 구매 주장을 구분해 읽어야 함
