  - compute와 storage를 독립적으로 최적화, 교체, 확장할 수 있고 compute 장애 후 기존 데이터에 새 노드를 연결할 수 있음

  - DB 전용 저장 계층은 필터를 저장 노드로 내려 필요한 행만 전송하는 predicate pushdown으로 트래픽을 줄임
  - 저장소의 계산 능력을 사용하므로 분리와 pushdown은 반대가 아니라 상호 보완적임
- 요지
  - 책임 분리는 독립 확장을 가능하게 하지만 새 경계의 통신 비용을 줄이는 공동 설계가 필요함

  - 데이터베이스 계층과 PostgreSQL 전용 저장 서비스를 분리하고 저장 서비스 내부에서도 로그 처리와 블록 저장을 분리함
  - 로그 처리 시스템이 데이터베이스 작업 일부를 저장 계층에 내려 compute의 I/O 병목을 줄임
  - 저장과 compute가 각자 부하에 맞게 확장되고 read pool은 같은 저장 데이터를 공유하며 수평 확장함
  - 여러 계층의 자동 캐시가 원격 저장의 지연을 줄이고 workload 패턴에 맞춰 데이터를 배치함
  - 저장 클러스터가 hotspot과 장애에 따라 동적으로 자원을 조정해 고정 크기 저장 노드의 한계를 줄임
- 해석 시 주의
  - 제품 공급자의 설명과 자체 성능 수치이므로 구조 설명과 비교 성능 주장을 구분해 읽어야 함
