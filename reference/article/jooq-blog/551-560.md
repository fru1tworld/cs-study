### jOOQ 3.2 라이선스 업데이트

3주 전, 저희는 유료 라이선스 계약을 통해 상용 데이터베이스 지원을 제공하는 새로운 듀얼 라이선스 프레임워크 하에 jOOQ 3.2를 공개하고 배포했습니다.

개발자 커뮤니티는 사용자 그룹에서 상당한 참여를 보여주었으며, 대체로 호의적인 반응이었습니다. 대부분은 라이선스 변경을 jOOQ의 지속적인 발전을 위한 긍정적인 신호로 보았지만, 일부 요소들은 정당한 질문이 필요했습니다.

중요한 우려 사항 중 하나는 "배포(distribution)" 용어와 관련하여 jOOQ 라이선스 1.0(10월 1일)의 문구에 관한 것이었습니다. 이는 jOOQ 라이선스 1.1(10월 28일)에서 수정되었으며, 라이선스 보유자가 "최종 사용자 애플리케이션과 함께 jOOQ를 배포하고 내장할 수 있음(§6.2)"을 명시적으로 허용합니다. 이는 고객에 대한 의도된 제약이 아니라 명확화를 나타냅니다. 업데이트된 라이선스는 기존 jOOQ 3.2 고객에게 즉시 적용되어 확장된 권리를 부여합니다.

라이선스 문의에 대한 FAQ가 참조용으로 게시되었습니다.

### jOOQ 3.3 전망

릴리스 3.3(2014년 초 목표)에는 다음과 같은 다양한 기능이 포함될 예정입니다:

- jOOQ Professional Edition에서 MS Access 지원
- 키셋 페이징 기능
- jOOQ 3.2+를 사용한 행 수준 보안 및 공유 스키마 멀티테넌시를 위한 SQL 변환 SPI 예제 구현
- 커뮤니티가 SPI 구현 및 추가 플러그인을 공유할 수 있는 오픈 소스 기여 플랫폼

추가 세부 정보는 GitHub 3.3.0 마일스톤에 나타나며, 사용자 그룹을 통해 참여할 수 있습니다.

### SQL 존 - 키셋 페이징

최근 뉴스레터에서는 NoSQL에 대해 논의했습니다. 그러나 SQL로 돌아가서 코드에 대한 통제력을 유지하는 것이 여전히 중요합니다. jOOQ 3.3은 "seek method"라고도 불리는 네이티브 키셋 페이징 지원을 제공할 예정입니다. 최근 블로그 게시물에서 이 메커니즘을 설명하고 대규모 데이터셋에서 상수 시간 페이징이 어떻게 작동하는지 보여줍니다. 이는 Twitter나 Facebook 스타일의 지연 데이터 로딩에 특히 유용합니다.

### SQL 존 - 유용한 SQL 기법들

주목할 만한 두 가지 SQL 기법:

- SELECT DISTINCT 쿼리에서 DENSE_RANK()를 대신 사용하여 ROW_NUMBER()를 생성하기. ROW_NUMBER()가 DISTINCT를 무효화하기 때문입니다.
- 집계된 데이터를 정규화하기 위해 재귀 SQL 사용하기 - 본질적으로 테이블의 그룹화와 집계를 해제하는 것입니다.

### SQL 존 - MySQL 파서 / jOOQ 코드 생성기

10월 10일 뉴스레터에서 GUDU Soft와 Data Geekery 간의 협력인 SQL2jOOQ를 발표했습니다. MySQL에서 jOOQ 코드로의 변환 작업이 상당히 진전되었습니다. 이 새로운 도구는 광범위한 수작업 문자열 기반 SQL을 포함하는 레거시 애플리케이션을 jOOQ로 마이그레이션하는 것을 용이하게 할 것입니다.

## 유용한 숨겨진 Eclipse 기능 Top 5

> 원문: https://blog.jooq.org/top-5-useful-hidden-eclipse-features/

게시일: 2013년 10월 27일, lukaseder 작성

---

Eclipse는 괴물입니다. 그 신비로움이 오직 그 강력함에 의해서만 능가되는 장치입니다. 어떤 사람들은 이것을 연속체 변환기(continuum transfunctioner)라고 부를 것입니다. 다른 사람들은 변형기(transmogrifier)라고 부를 것입니다. 네, 이것은 너무 거대해서 마스터하는 데 수년이 걸립니다. 그리고 나서, 당신의 매니저가 나타나서 말합니다: 우리는 이제 NetBeans를 사용합니다. 농담입니다. Adam Bien을 제외하고는 아무도 NetBeans를 사용하지 않습니다. 그러니 매우 유용하지만 숨겨진 5가지 Eclipse 기능을 살펴봅시다.

### 1: 내가 가장 좋아하는 기능: 즐겨찾기(Favourites)

모든 사람은 정적 메서드가 있는 라이브러리를 사용합니다. Java 5부터 우리는 이것들을 정적 import할 수 있어서, 더 이상 다음과 같은 것을 작성할 필요가 없습니다:

```java
SomeVeryImportantUtility.split(string1, string2);
```

하지만 누가 이 메서드들을 참조하는 모든 클래스에서 수동으로 정적 import하겠습니까? 아무도 안 합니다. 왜냐하면 환경설정에서 즐겨찾는 타입과 멤버를 정의할 수 있기 때문입니다:

[스크린샷: Preferences > Favorites]

그리고 나서, 타이핑을 시작하고 자동 완성을 찾아보세요:

[스크린샷: 자동 완성]

자동 완성은 필요한 정적 import도 생성합니다. 예를 들어 많은 함수가 있는 DSL을 사용할 때 매우 유용합니다. 분명히, 당신은 어떤 것이 정말로 당신이 즐겨찾는 라이브러리인지, 그리고 그 라이브러리들 중에서 어떤 것이 당신이 즐겨찾는 타입인지 신중하게 결정하고 싶을 것입니다. 당신이 jOOQ 블로그(또는 그 신디케이션)에 있으니, 힌트를 드리겠습니다. 항상 `org.jooq.impl.DSL`을 즐겨찾기에 추가하세요.

### 2: 멋진 블록 선택 모드

저는 최근에 여기에 대해 블로그에 글을 썼습니다. 이것은 너무 멋져서, 한 번 더 언급할 가치가 있습니다.

[스크린샷: 강조된 버튼이 있는 블록 선택 모드]

블록 선택

왼쪽에서 여섯 번째에 있는 강조된 버튼을 주목하세요. 그것이 멋진 "블록 선택 모드"입니다 (Windows에서는 Alt-Shift-A, 또는 Ctrl+3을 누른 다음 block selection을 입력). 이것은 선택된 각 줄의 같은 위치에 여는 따옴표를 쓸 수 있게 해줍니다. 이것은 거의 동일한 많은 양의 줄을 편집해야 할 때 매우 유용합니다.

### 3: EGit 스테이징 뷰

분명히, 모든 EGit 사용자가 이 뷰를 알고 있는 것은 아닙니다. 사실, 저에게 이 뷰는 제가 쉘 명령을 사용하지 않는 가장 중요한 이유입니다. 이 아름다움을 확인해 보세요:

[스크린샷: 스테이징 뷰]

좋아요, 정말 아름답지는 않네요. Eric Burke의 이 만화 스트립이 생각납니다. 하지만 우리는 변형기 세계에 있고, 스테이징 뷰는 저장소를 원격 저장소와 동기화하면 추가/커밋/푸시되기를 기다리는 변경 사항들로 채워집니다. 이제 저는 줄 단위로, 어떤 변경 사항을 인덱스에 추가할지 결정할 수 있습니다 (제가 main 메서드를 추가하지 않았다는 점에 주목하세요). 이것은 스테이징된(추가된) 변경 사항과 스테이징되지 않은(아직 추가되지 않은) 변경 사항이 있게 됩니다. EGit에서 항상 그렇듯이, 저는 이제 바로 커밋하거나, 커밋+푸시하거나, 수정+커밋하거나, 수정+커밋+푸시를 한 번에 할 수 있습니다. 명령줄에서 그렇게 해보세요. 이제 이 첫 번째 커밋 후에, 저는 다시 main 메서드를 별도의 커밋으로 스테이징/추가할 수 있습니다. 제 생각에, 뒤에서는 이것이 스태싱이나 다른 종류의 로컬 캐시를 사용하여 구현되어 있을 것 같습니다. 신경 쓰지 않습니다, 이것은 아름답습니다! 아마도 이 아름다움으로 훨씬 더 많은 것을 할 수 있을 텐데, 그것은 책 한 권 분량이 될 것입니다 (저는 그런 책을 기다리고 있습니다, [@niborst](https://twitter.com/niborst), 이것을 읽고 있다면요). 위의 Git 이야기를 하나도 이해하지 못했다면, 이 인기 있는 가이드를 시도해 보거나, 저와 함께...

### 4: 타입 필터

네, 왜냐하면 "Eclipse의 기본 자동 완성은 넌센스"이기 때문입니다. 네, 맞습니다! 아무도 API에서 `hashCode()`나 `wait()`나 `notifyAll()`을 정말로 호출하고 싶어하지 않습니다. 절대로. 사실, 요즘에는 JDK의 동시성 라이브러리를 작성하는 경우를 제외하고는 락 객체에서조차 `wait()`나 `notify()`를 호출하는 사람이 거의 없습니다. 하지만 다행히 다른 누군가가 그것을 무료로 하고 있고, 그들은 분명히 vi나 emacs나 헥스 에디터를 사용하고 있으므로, `Object` 메서드를 신경 쓰지 않습니다. 그렇다면, 왜 제 자동 완성 팝업이 이 넌센스로 가득 차 있을까요? 클래스를 하나 만들어 봅시다...

## jOOQ에서 Seek 메서드를 사용한 더 빠른 SQL 페이징

> 원문: https://blog.jooq.org/faster-sql-paging-with-jooq-using-the-seek-method/

### 개요

이 블로그 글은 "Seek 메서드"(또는 "keyset 페이징"이라고도 함)를 설명합니다. 이는 대용량 데이터셋에서 전통적인 OFFSET 기반 페이징보다 뛰어난 성능을 보이는 대안적인 페이징 기법입니다.

### OFFSET의 문제점

전통적인 오프셋 페이징은 결과를 반환하기 전에 데이터베이스가 이전의 모든 레코드를 건너뛰고 카운트해야 합니다. 단순한 쿼리는 적절하게 수행되지만:

```sql
SELECT first_name, last_name, score
FROM players
WHERE game_id = 42
ORDER BY score DESC
LIMIT 10;
```

더 높은 페이지 번호로 페이징할수록 점점 더 느려집니다:

```sql
SELECT first_name, last_name, score
FROM players
WHERE game_id = 42
ORDER BY score DESC
LIMIT 10
OFFSET 100000;
```

### Seek 메서드의 작동 방식

Seek 메서드는 레코드를 건너뛰는 대신, "seek 조건자"를 사용하여 마지막으로 조회한 행 이후의 레코드를 가져옵니다. 예를 들어, `OFFSET 10`을 사용하는 대신, 결과가 마지막 플레이어의 점수 이후부터 시작해야 한다고 지정합니다:

```sql
SELECT first_name, last_name, score
FROM players
WHERE game_id = 42
AND score < 949
ORDER BY score DESC
LIMIT 10;
```

중복된 점수 값을 처리하기 위해, 조건자에 유니크 컬럼을 포함시킵니다:

```sql
SELECT player_id, first_name, last_name, score
FROM players
WHERE game_id = 42
AND (score, player_id) < (949, 15)
ORDER BY score DESC, player_id DESC
LIMIT 10;
```

### 주요 장점

- 성능: 전체 테이블 순회 대신 인덱스 범위 스캔을 통해 페이지 깊이와 관계없이 일정한 시간 내에 실행됩니다
- 안정성: "안정적인" 페이징 - 삽입이나 삭제가 발생해도 페이지 간에 중복 레코드가 발생하지 않습니다
- 확장성: 벤치마크 데이터에 따르면 높은 페이지 번호에서 극적으로 개선된 성능을 보여줍니다

### jOOQ 3.3 구현

jOOQ는 `SEEK` 절을 통해 네이티브 구문 지원을 제공합니다:

```java
DSL.using(configuration)
   .select(PLAYERS.PLAYER_ID, PLAYERS.FIRST_NAME,
           PLAYERS.LAST_NAME, PLAYERS.SCORE)
   .from(PLAYERS)
   .where(PLAYERS.GAME_ID.eq(42))
   .orderBy(PLAYERS.SCORE.desc(), PLAYERS.PLAYER_ID.asc())
   .seek(949, 15)
   .limit(10)
   .fetch();
```

이 접근 방식은 비교 조건자를 수동으로 구성하는 것보다 페이징 로직을 더 읽기 쉽게 만들면서 타입 안전성을 제공합니다.

## 데이터 정규화를 위한 재귀 SQL

> 원문: https://blog.jooq.org/recursive-sql-for-data-normalisation/

게시일: 2013년 10월 24일
작성자: lukaseder

### 문제 상황

이 글에서는 집계된 데이터를 정규화하기 위해 재귀 SQL을 사용하는 방법을 다룹니다. 여기서 다루는 시나리오는 날짜-이벤트 데이터에서 집계된 건수를 개별 레코드로 "역집계"해야 하는 경우입니다.

초기 데이터:
| 날짜 | 건수 |
|------|-------|
| 2013년 10월 01일 | 2 |
| 2013년 10월 02일 | 1 |
| 2013년 10월 03일 | 3 |
| 2013년 10월 04일 | 4 |
| 2013년 10월 05일 | 2 |
| 2013년 10월 06일 | 0 |
| 2013년 10월 07일 | 2 |

원하는 출력: 각 날짜에 대해 1부터 COUNT까지 번호가 매겨진 개별 레코드 (이벤트가 0인 날짜는 제외).

### SQL 솔루션

이 글에서는 재귀 공통 테이블 표현식(CTE) 접근 방식을 제시합니다:

```sql
with recursive

-- 원본 데이터 정의
data(date, count) as (
  select date '2013-10-01', 2 union all
  select date '2013-10-02', 1 union all
  select date '2013-10-03', 3 union all
  select date '2013-10-04', 4 union all
  select date '2013-10-05', 2 union all
  select date '2013-10-06', 0 union all
  select date '2013-10-07', 2
),

-- 재귀 CTE: count가 0보다 큰 데이터로 시작하여 count가 1이 될 때까지 1씩 감소시킴
recurse(date, count) as (
  select date, count
  from data
  where count > 0
  union all
  select date, count - 1
  from recurse
  where count > 1
)
select date, count event_number from recurse
order by date asc, event_number asc;
```

### 작동 원리

재귀 CTE는 `count > 0`인 모든 레코드로 시작한 다음, 1에 도달할 때까지 각 count에서 1을 재귀적으로 뺍니다. 이렇게 하면 원하는 비정규화된 출력이 생성됩니다.

### PostgreSQL 대안 접근법

저자는 `generate_series`를 사용하는 우아한 PostgreSQL 전용 솔루션을 언급합니다:

```sql
with recursive
-- 원본 데이터 정의
data(date, count) as (
  select date '2013-10-01', 2 union all
  select date '2013-10-02', 1 union all
  select date '2013-10-03', 3 union all
  select date '2013-10-04', 4 union all
  select date '2013-10-05', 2 union all
  select date '2013-10-06', 0 union all
  select date '2013-10-07', 2
)
-- generate_series를 사용하여 1부터 count까지의 시퀀스를 직접 생성
select date, generate_series(1, count) event_number
from data
where count > 0
order by date asc, event_number asc;
```

### 참고 사항

이 글에서는 Oracle의 CONNECT BY 절이 이 특정 사용 사례에는 적합하지 않았다고 언급합니다.

많은 무료 오픈 소스 제품들은 이런 방식으로 작동하지 않습니다. 무료이고 LGPL 라이선스라는 점으로 여러분을 유인한 후, 나중에야 많은 컨설팅 및 유지 보수 비용을 여러분에게 떠넘깁니다. 선택은 여러분의 것입니다. 유지 보수 비용을 낮게 유지하여 미래에 투자하고 싶으신가요? 아니면 싼 제품을 얻고 나중에 지불하고 싶으신가요? 엄청나게 싼 잉크젯 프린터와 빨리 비워지는 잉크 카트리지에 나중에 얼마나 지불하게 될지 생각해 보세요. 엄청나게 싼 커피 머신과 그 캡슐에 나중에 얼마나 지불하게 될지 생각해 보세요. 일부 컴퓨터 제품과, "이전" 마이너 릴리스의 운영 체제가 더 이상 지원되지 않기 때문에 터무니없는 업데이트에 얼마나 자주 지불해야 하는지 생각해 보세요.

## 오픈 소스와 상용 소프트웨어의 중요한 차이

> 원문: https://blog.jooq.org/a-significant-difference-between-open-source-and-commercial-software/

최근의 한 사건이 오픈 소스의 장단점에 관한 논쟁에 상당한 관심을 불러일으켰습니다. 오픈 소스 소프트웨어에 대한 Oracle의 공격은 기술 커뮤니티 전반에서 큰 논의를 촉발시켰습니다. Red Hat처럼 포지셔닝되지 않은 대기업들에게는 명확한 입장을 취하는 것이 어려운 일입니다. Oracle은 역사적으로 상용 소프트웨어만 판매해왔지만, Sleepycat Software(BerkeleyDB)와 Sun Microsystems(Java, MySQL)를 포함한 수많은 오픈 소스 회사들을 인수했습니다. 이러한 혼합된 레거시를 중심으로 장기 전략을 수립하는 것은 어려운 일입니다.

Oracle은 IBM의 매출을 넘어 전 세계에서 두 번째로 큰 소프트웨어 회사가 되면서 여전히 매우 성공적인 기업으로 남아있습니다. 주력 제품인 Java와 Oracle 데이터베이스의 지속적인 인기는 jOOQ와 같은 솔루션을 제공하는 미들웨어 벤더들에게 좋은 징조입니다.

Data Geekery에서는 새로 채택한 상용 라이선싱과 함께 오픈 소스가 여전히 중요합니다. 듀얼 라이선싱으로의 전환은 jOOQ 사용자 그룹에서 대체로 긍정적인 반응을 받았지만, 지속적인 오픈 소스 헌신에 대한 의문을 제기하기도 했습니다. 오픈 소스와 상용 소프트웨어를 근본적으로 구분하는 것은 무엇일까요?

Adobe의 Dr. Roy Fielding은 오픈 소스와 상용 소프트웨어 사이에 본질적인 차이가 거의 없다고 자주 인용됩니다 - 둘 다 각자의 장단점을 가진 실행 가능한 비즈니스 모델을 나타냅니다.

한 가지 중요한 차이점이 드러납니다: 저품질 오픈 소스 소프트웨어는 저품질 상용 소프트웨어보다 훨씬 더 오래 살아남을 수 있습니다. 실패한 오픈 소스 소프트웨어 "판매"로 아무도 수익을 잃지 않기 때문에, 저품질 프로젝트들은 무한정 지속됩니다. 저자는 이전에 이러한 저품질 오픈 소스 이니셔티브를 인식하는 방법에 대해 논의한 바 있습니다.

오픈 소스는 근본적으로 미션인 동시에 비즈니스 및 마케팅 전략을 나타냅니다. 소프트웨어 벤더들은 이러한 접근 방식이 자신들의 이익에 유리하게 작용하는지 불리하게 작용하는지 평가해야 합니다.

## JVM에 약간의 엔트로피를 추가하라

> 원문: https://blog.jooq.org/add-some-entropy-to-your-jvm/

진정한 난수를 생성하는 것은 어렵습니다. 유명한 XKCD 만화처럼 "공정한 주사위 굴림으로 선택됨. 무작위성 보장됨"이라고 말하며 항상 4를 반환하는 것은 분명히 좋은 해결책이 아닙니다. `java.math.Random.nextInt()`가 상수 값을 반환하도록 수정하는 것도 마찬가지로 터무니없는 방법입니다.

그래서 여기 더 나은 아이디어가 있습니다: JVM이 시작될 때 `java.lang.Integer.IntegerCache`를 다시 작성하는 것입니다!

```java
import java.lang.reflect.Field;
import java.util.Random;

public class Entropy {
  public static void main(String[] args)
  throws Exception {
    // 리플렉션을 통해 IntegerCache를 추출
    Class<?> clazz = Class.forName(
      "java.lang.Integer$IntegerCache");
    Field field = clazz.getDeclaredField("cache");
    field.setAccessible(true);
    Integer[] cache = (Integer[]) field.get(clazz);

    // Integer 캐시를 다시 작성
    for (int i = 0; i < cache.length; i++) {
      cache[i] = new Integer(
        new Random().nextInt(cache.length));
    }

    // 무작위성 증명
    for (int i = 0; i < 10; i++) {
      System.out.println((Integer) i);
    }
  }
}
```

위 프로그램의 출력은 다음과 같습니다:

```
92
221
45
48
236
183
39
193
33
84
```

물론, JVM 파라미터 `-XX:AutoBoxCacheMax=<size>`를 사용하여 IntegerCache를 확장하면 더 많은 엔트로피를 얻을 수 있습니다.

면책 조항: 이 코드는 Apache 2.0 라이선스에 따라 제공됩니다. 사용에 따른 모든 책임은 사용자에게 있습니다.

## 미국 인터넷 거버넌스의 종말

> 원문: https://blog.jooq.org/the-end-of-us-internet-governance/

*2013년 10월 12일 작성 - lukaseder*

인터넷은 마침내 본래 될 수 있었던 진정한 글로벌 네트워크가 될 것입니다. ICANN, IANA, IETF 및 기타 기관들이 동시에 미국의 일방적인 인터넷 거버넌스에서 벗어나고 있기 때문입니다.

internetgovernance.org의 기사에 따르면, 핵심 인터넷 기관들이 미국 정부의 통제에서 벗어나고 있습니다.

결국, NSA가 자신들의 감시 활동으로 우리 모두에게 '호의'를 베풀어 준 셈이 되었습니다.

이 변화가 어떤 결과를 가져올지는 불확실합니다. 이 변화가 인터넷을 개선할 수도 있지만, UN 스타일의 정치적 과정을 도입하는 것은 기회와 도전 모두를 제시합니다.

이러한 발전에 관해 Reddit에서 논의에 참여하실 수 있습니다.

## Eclipse의 놀라운 블록 선택 모드

> 원문: https://blog.jooq.org/eclipses-awesome-block-selection-mode/

이 글은 메뉴에 완전히 숨겨져 있어 과소평가되고 있지만, 수많은 상황에서 매우 유용한 놀라운 Eclipse 기능에 대한 것입니다. 바로 Windows에서 Alt-Shift-A로 토글할 수 있는 놀라운 "블록 선택 모드"입니다. 다음은 블록 선택 모드를 위한 예제 과제입니다:

Eclipse를 사용하여 Java 문자열 리터럴에 깔끔하게 포맷된 SQL 쿼리를 작성(복사-붙여넣기)할 수 있는 방법이 있을까요?

다음은 4단계 시각적 가이드로 답변을 제공합니다:

1단계: 붙여넣기

포맷된 SQL 문을 Java 파일에 그대로 붙여넣습니다.

2단계: 여는 따옴표 작성

강조 표시된 버튼(왼쪽에서 여섯 번째)을 주목하세요. 이것이 바로 놀라운 "블록 선택 모드"(Windows에서 Alt-Shift-A)입니다. 이 모드를 사용하면 선택한 각 줄의 동일한 위치에 여는 따옴표를 작성할 수 있습니다.

3단계: 닫는 따옴표와 연결 연산자 작성

닫는 따옴표와 연결 기호(+)에 대해서도 동일한 기법을 적용합니다.

4단계: 세미콜론 수정

여기에는 별도의 설명이 필요 없습니다.
