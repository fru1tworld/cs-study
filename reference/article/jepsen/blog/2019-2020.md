# Jepsen 블로그 2019-2020

## FaunaDB 2.5.4

날짜: 2019-03-04

Fauna와 Jepsen은 협력하여 FaunaDB(Calvin 프로토콜 기반의 분산 트랜잭션 문서 저장소)에서 19개 문제를 발견했습니다.

### 주요 발견 사항

- 스키마 변경 및 가용성 관련 경미한 문제들
- 인덱스가 음수 정수값 반환 실패, 페이지 끝 레코드 누락, 읽기 왜곡(read skew) 발생
- 임시 쿼리가 요청된 타임스탬프보다 오래된 상태 관찰
- 개발 릴리스에서 단조성 없는 읽기(non-monotonic reads), 장기 포크(long forks), 읽기 왜곡 발견
- 기본 키-값 연산은 워크로드에 따라 스냅샷 격리부터 엄격한 직렬화까지 제공

### 해결 상황

"FaunaDB는 2.6.0 버전에서 발견된 모든 심각한 문제를 해결했으며, 동시 스키마 수정" 같은 경미한 문제의 수정은 향후 릴리스에 예정되어 있습니다.

## YugaByte DB 1.1.9

날짜: 2019-03-25

YugaByte와의 협력을 통해, Jepsen 분석은 YugaByte DB 버전 1.1.9에서 세 가지 중요한 안전성 취약점을 확인했습니다:

1. 정상 작동 조건에서 발생하는 읽기 왜곡(read skew)과 데이터 손상
2. 클럭 스큐(clock skew) 이벤트 중 발생하는 읽기 왜곡과 데이터 손상
3. 여러 네트워크 분할이 포함된 드문 상황에서 승인된 삽입의 손실

### 해결 현황

"YugaByte DB는 이 세 가지 문제와 여러 다른 문제들을 1.2.0 버전에서 모두 해결했습니다."

## TiDB 2.1.7

날짜: 2019-06-11

Jepsen은 PingCAP과 함께 TiDB 2.1.7부터 3.0.0-rc.2 버전까지 테스트를 수행했습니다.

### 발견된 문제

테스트 결과에 따르면, 기본 설정에서 TiDB는 "스냅샷 격리를 위반하여 읽기 왜곡(read skew), 손실된 업데이트(lost updates), 그리고 호환되지 않는 순서(incompatible orders)를 허용"했습니다.

문제의 원인은 두 개의 별도 자동 재시도 메커니즘이 충돌하는 쓰기를 무분별하게 다시 적용했기 때문입니다.

### 해결 현황

버전 3.0.0-rc.2에서는 기본 설정을 변경하여 스냅샷 격리를 기본으로 제공하도록 개선했으며, 테이블 생성 시 발생하던 경합 조건과 시작 시 발생하던 일부 충돌 현상도 수정했습니다.

## YugaByte DB 1.3.1

날짜: 2019-09-04

Jepsen은 YugaByte DB 버전 1.3.1의 베타 직렬화 가능 SQL 트랜잭션 지원에 초점을 맞춰 공동 분석을 수행했습니다. 평가 결과 여러 안전성 문제가 확인되었습니다.

### 주요 발견사항

- `DEFAULT` 컬럼 초기화를 `NULL`로 설정하는 경합 조건
- 태블릿 서버가 마스터 노드 연결을 잃을 때 발생하는 직렬화 가능성 위반(G2-item)
- 테이블 생성과 관련된 DDL 문 문제
- 네트워크 분할 시 느린 복구와 프로세스 누수를 포함한 가용성 문제

### 해결 현황

YugaByte는 G2 직렬화 가능성 문제와 일부 추가 버그를 해결했으며, 나머지 문제에 대한 작업을 계속하고 있습니다.

## etcd 3.4.3

날짜: 2020-01-29

Jepsen과 etcd 팀이 협력하여 etcd의 핵심 기능들을 검증했습니다. 검증 대상은 키-값 연산, 잠금(locks), 그리고 감시(watches) 기능이었습니다.

### 주요 발견사항

#### 키-값 연산과 감시 기능: 안전성 문제 없음
- 다중 키 트랜잭션을 포함한 키-값 연산이 "엄격한 직렬화(strict serializable)"로 작동
- 감시 기능이 키의 모든 변경사항을 순서대로 전달 (revision zero 관련 미문서화된 엣지 케이스 제외)

#### 잠금 기능: 근본적인 결함 발견
- 비동기 네트워크 환경에서 상호 배제(mutual exclusion)를 보장할 수 없음
- 이론적 위험을 악화시킨 구현 버그 존재 (master 버전에서 수정됨)

### 후속 조치

etcd 팀이 안전성 보장에 대한 새로운 문서화를 준비 중입니다.

## MongoDB 4.2.6

날짜: 2020-05-14

Jepsen에서 수행한 MongoDB 4.2.6의 트랜잭션 시스템 조사에 따르면, 해당 버전은 "완전한 ACID" 보증을 주장했음에도 불구하고 스냅샷 격리 위반 사항이 발견되었습니다.

### 주요 발견 사항

약한 기본 설정이 트랜잭션에서 쓰기 손실과 신중하게 제어하지 않으면 오래된 읽기를 허용할 수 있다는 점입니다.

## PostgreSQL 12.3

날짜: 2020-06-11

Jepsen은 PostgreSQL 12.3에서 직렬화 가능성 위반(serializability violation)을 발견했습니다. 이 결함은 "동시 삽입과 업데이트로 인해 트랜잭션들이 서로의 효과를 관찰하지 못하는" 문제를 야기합니다.

### 주요 사항

- 이 버그는 버전 9.1에서 직렬화 가능한 스냅샷 격리(serializable snapshot isolation)가 구현된 이후로 존재해온 것으로 보입니다
- 패치는 다음 마이너 릴리스에서 제공될 예정이며, 현재 8월 13일 출시가 예정되어 있습니다

## Redis-Raft 1b3fbf6

날짜: 2020-06-22

Jepsen은 Redis Labs의 Redis-Raft 초기 개발 빌드를 검증하는 데 지원했습니다. 분석 결과 21개의 문제를 발견했는데, 이는 다음을 포함합니다:
- 충돌(crashes)
- 분열 뇌(split-brain)
- 무한 루프(infinite loops)
- 중단된 읽기(aborted reads)
- 데이터 손상(data corruption)
- 모든 장애 조치 시 전체 데이터 손실(total data loss on any failover)

Redis Labs는 이들 문제 중 하나를 제외한 모든 문제를 최근 버전에서 해결했으며, 2021년 일반 공개를 목표로 계속 작업하고 있습니다.

## Scylla 4.2-rc3

날짜: 2020-12-22

Jepsen은 ScyllaDB 팀과 협력하여 Scylla에서 일곱 가지 문제점을 발견했습니다.

### 주요 문제

- 경량 트랜잭션(LWT) 분열 뇌 현상: 건강한 클러스터에서도 발생하며, 불완전한 행 해시코드와 멤버십 변경 관련 여러 문제가 원인입니다.

- 문서화 문제: "비-LWT 작업은 격리되고 원자적"이라는 부정확한 주장과 멤버십 작업의 법률적 규칙이 문서화되지 않았습니다.

### 현황

ScyllaDB는 패치와 문서 개선을 통해 거의 모든 오류를 수정했으며, 남아있는 분열 뇌 현상은 동시 멤버십 변경으로 제한되어 있습니다.
