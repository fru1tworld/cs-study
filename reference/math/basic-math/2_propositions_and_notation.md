# 명제와 수학 표기

> 원문: https://softwarefoundations.cis.upenn.edu/current/lf-current/Logic.html

## 명제

명제는 참인지 거짓인지 논할 수 있는 문장이다. `2 + 2 = 4`, 모든 자연수 `n`에 대해 `n + 0 = n`이 성립한다는 문장, `n × n = 9`를 만족하는 자연수가 있다는 문장이 이에 해당한다. 질문이나 명령, 정의되지 않은 표현은 그대로는 명제가 아니다. Rocq에서는 명제가 `Prop` 타입에 속한다.

## 변수와 범위

변수는 정해진 영역(domain)의 임의 대상을 나타낸다. 한정사(quantifier)나 함수가 묶은 변수는 bound variable이고, 바깥 문맥에서 의미를 받아야 하는 변수는 free variable이다. 같은 문자를 쓰더라도 묶인 범위가 다르면 서로 다른 변수일 수 있다.

```text
∀ x, P x → ∃ x, Q x
```

위 식에서 두 한정사가 도입한 `x`는 각각 다른 범위에 묶여 있다. 따라서 변수 이름만 보지 말고 어느 한정사의 범위에 속하는지 따라 읽어야 한다.

## equality

`x = y`는 두 값이 같다는 명제다. 방향을 바꾸어 `y = x`로 읽을 수 있고, 식 안에서 같은 값끼리 치환할 수도 있다. 정의를 펼쳐 계산한 결과가 같다면 `reflexivity`로 증명이 끝날 수 있다. 계산만으로 끝나지 않는 경우에는 별도의 정리를 이용한 rewriting이나 귀납법이 필요할 수 있다.

## conjunction

`P ∧ Q`는 P와 Q가 모두 참이라는 뜻이다. 따라서 이를 증명하려면 두 명제를 각각 증명해야 한다. 반대로 가정으로 주어졌다면 P와 Q를 각각 꺼내 사용할 수 있다.

```text
n = 0 ∧ m = 0
```

위 명제도 `n = 0`과 `m = 0`이라는 두 등식을 모두 만족해야 한다.

## disjunction

`P ∨ Q`는 둘 중 적어도 하나가 참이라는 뜻으로, 둘 다 참인 경우도 허용한다. 증명할 때는 어느 쪽을 증명할지 선택하면 된다. 반면 가정으로 사용할 때는 어느 쪽이 성립하는지 정해져 있지 않으므로 두 경우를 모두 처리해야 한다.

## implication

`P → Q`는 P가 참이라고 가정했을 때 Q를 도출할 수 있다는 뜻이다. 증명에서는 P의 증명을 가정하고, 이를 이용해 Q의 증명을 구성한다. 이 관계가 P와 Q의 인과관계나 시간 순서를 뜻하지는 않는다. 방향도 중요하므로 `P → Q`와 `Q → P`는 일반적으로 다른 명제다.

## equivalence

`P ↔ Q`는 양방향 함의를 묶은 명제로, `P → Q`와 `Q → P`를 모두 증명해야 한다. 이렇게 얻은 동치는 정의를 대체하거나 명제를 rewriting할 때 자주 사용한다.

## negation

구성적 논리에서 `¬P`는 `P → False`의 약어다. P를 가정하면 모순을 이끌어 낼 수 있다는 뜻이므로, 단순히 P의 증명을 아직 찾지 못한 상태와는 다르다.

## 참과 거짓

- `True`
  - 항상 증명 가능한 proposition
- `False`
  - constructor가 없어 직접 proof를 만들 수 없는 proposition
- `False`를 얻으면 어떤 proposition도 도출 가능
- contradiction proof는 가정에서 `False`를 만드는 구조

## universal quantifier

`∀ x : A, P x`는 A의 모든 x에 대해 `P x`가 성립한다는 뜻이다. 증명할 때는 임의의 x를 도입해 `P x`를 보인다. 이미 증명된 명제를 특정 `a : A`에 적용하면 `P a`를 얻는다.

```text
∀ n : ℕ, n + 0 = n
```

위 명제를 증명할 때도 n을 특정 숫자로 정하지 않고 임의의 자연수로 다뤄야 한다.

## existential quantifier

`∃ x : A, P x`는 `P x`를 만족하는 x가 하나 이상 있다는 뜻이다. 이를 증명하려면 증인(witness)을 하나 제시하고 그 값이 성질을 만족함을 보여야 한다. 가정으로 주어졌다면 증인에 이름을 붙이고 그 성질의 증명을 꺼내 사용한다.

```text
∃ n : ℕ, n + 1 = 3
```

위 예제에서는 증인으로 2를 제시한 뒤 `2 + 1 = 3`을 증명하면 된다.

## precedence와 괄호

- 표기는 precedence 규칙에 따라 묶임
- 확실하지 않으면 괄호로 구조를 명시
- 다음 두 명제는 다름

```text
(P ∨ Q) → R
P ∨ (Q → R)
```

- theorem statement를 읽을 때 가장 바깥 connective부터 찾기

## quantifier 순서

- quantifier 순서가 의미를 바꿈

```text
∀ x, ∃ y, R x y
∃ y, ∀ x, R x y
```

첫 번째 식에서는 x마다 다른 y를 골라도 된다. 두 번째 식에서는 먼저 고른 하나의 y가 모든 x에 대해 관계를 만족해야 한다.

## proposition과 Boolean

명제(proposition)는 증명의 대상이며 반드시 자동으로 계산할 수 있어야 하는 것은 아니다. Boolean은 계산 결과가 `true` 또는 `false`인 데이터다. 계산 결과로 논리적 성질을 판단하려면 둘이 대응한다는 정확성 정리가 필요하다.

```text
evenb n = true ↔ Even n
```

위 식의 왼쪽은 계산 결과에 관한 등식이고 오른쪽은 논리적 성질이다. 이처럼 계산과 논리적 성질을 연결하는 것을 reflection이라고 부른다.

## theorem statement 읽는 절차

1. 모든 변수의 type 확인
2. 가장 바깥 quantifier 확인
3. 가장 바깥 implication 또는 connective 확인
4. 가정과 결론을 자연어로 다시 씀
5. equality와 relation의 argument 순서 확인

## 예제 읽기

```text
∀ n m : ℕ, n = m → n + n = m + m
```

임의의 자연수 n과 m을 택하고 `n = m`을 가정한 뒤, `n + n = m + m`을 보이라는 뜻이다. 가정의 등식을 이용해 치환하면 증명할 수 있다.

```text
∀ n : ℕ, n = 0 ∨ ∃ m, n = m + 1
```

이 명제는 모든 자연수가 0이거나 어떤 자연수의 후속자(successor)라는 분류다. 자연수에 대한 경우 분석이나 귀납법이 이 구조와 연결된다.

## 자체 점검

- `P ∧ Q → P`를 자연어로 읽기
- `P → Q → R`에서 어떤 가정을 순서대로 도입하는지 설명
- `∀ x, P x`와 `∃ x, P x`의 증명 data 차이 설명
- `¬P`를 implication으로 다시 쓰기
- `∀ x, ∃ y, x < y`의 witness를 어떻게 고를지 생각
- `∃ y, ∀ x, x < y`가 자연수에서 참인지 판단
