# RFC 894 - 이더넷 네트워크에서의 IP 데이터그램 전송 표준

```
Network Working Group                                     Charles Hornig
Request for Comments: 894            Symbolics Cambridge Research Center
                                                              April 1984
```

## Abstract

이 RFC는 이더넷 [2]에서 인터넷 프로토콜(IP) [1] 데이터그램을 캡슐화하는 표준 방법을 규정한다.

## 1. 서론

- 이 문서 적용 대상: 이더넷(10메가비트/초, 48비트 주소)
- 실험적 이더넷(3메가비트/초, 8비트 주소)에서의 IP 데이터그램 전송 절차 → [3]에 기술

## 2. 프레임 형식

IP 데이터그램은 표준 이더넷 프레임으로 전송한다. 프레임의 타입 필드는 16진수 0800이어야 하며(MUST), 데이터 필드에는 IP 헤더와 IP 데이터가 차례로 들어간다.

데이터 필드의 최소 길이는 46옥텟이다. 이보다 짧다면 값이 0인 옥텟으로 패딩해 최소 프레임 크기를 맞춰야 한다(MUST). 이 패딩은 IP 패킷의 일부가 아니므로 IP 헤더의 전체 길이에는 포함하지 않는다.
- 데이터 필드 최대 길이: 1500옥텟 → 이더넷으로 전송되는 IP 데이터그램의 최대 길이도 1500옥텟
  - 구현은 전체 길이 패킷을 지원하도록 권장(SHOULD)
  - 게이트웨이 구현: 전체 길이 패킷을 수신하고 필요시 단편화할 준비가 되어 있어야 함(MUST)
  - 시스템이 전체 길이 패킷을 수신할 수 없는 경우 → TCP 최대 세그먼트 크기 옵션 [4] 사용 등으로 다른 호스트가 보내지 않게 해야 함
이더넷의 데이터그램은 일반 인터넷 기본 최대 패킷 크기인 576옥텟보다 클 수 있다. 다른 이더넷에 있는 호스트로 보낼 때는 중간 게이트웨이에서 불필요하게 단편화되지 않도록 더 작은 데이터그램을 사용하는 것이 적절할 수 있다.

## 3. 주소 매핑

32비트 인터넷 주소를 48비트 이더넷 주소에 대응시키는 방법은 다음과 같다.

- 정적 테이블
  - 각 호스트에 로컬 네트워크의 다른 모든 호스트에 대해, 이더넷 주소와 인터넷 주소를 담은 테이블 제공 가능
- 동적 발견
  - 32비트 인터넷 주소와 48비트 이더넷 주소 간의 매핑 → 주소 해석 프로토콜(ARP) [5]을 통해 수행 가능
  - 인터넷 주소는 인터넷 네트워크에서 임의로 할당
  - 각 호스트의 구현: 자신의 인터넷 주소를 알아야 하고(MUST) 이더넷 주소 해석 패킷에 적절히 응답해야 함(MUST)
  - 필요할 때 인터넷 주소를 이더넷 주소로 변환하기 위해 ARP를 사용해야 함(MUST)
- 브로드캐스트 주소
  - 브로드캐스트 인터넷 주소(호스트 부분이 모두 이진수 1인 네트워크 주소) → 브로드캐스트 이더넷 주소(모두 이진수 1, `FF-FF-FF-FF-FF-FF` 16진수)로 매핑되어야 함(MUST)
- ARP 동적 발견 절차의 사용을 강력히 권장

## 4. 트레일러 형식

일부 Unix 4.2bsd 버전은 VAX 가상 메모리 아키텍처에서 네트워크 성능을 높이기 위해 다른 캡슐화 방법을 사용한다. 같은 이더넷에서 서로 합의한 시스템은 이 형식으로 통신할 수 있지만, 모든 호스트가 구현해야 하는 것은 아니다. 따라서 수신자가 해석할 수 있다는 확신이 없으면 이 형식의 데이터그램을 보내서는 안 된다(MUST NOT). 자세한 트레일러 캡슐화 방법은 [6]에 있다.

## 5. 바이트 순서

- 인터넷 프로토콜 명세 [1]의 부록 B에 설명된 대로 → IP 데이터그램은 이더넷에서 8비트 바이트의 연속으로 전송
