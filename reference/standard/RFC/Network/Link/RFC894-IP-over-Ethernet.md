        이더넷 네트워크에서의 IP 데이터그램 전송 표준


### Abstract

이 RFC는 이더넷 [2]에서 인터넷 프로토콜(IP) [1] 데이터그램을 캡슐화하는
표준 방법을 규정한다.


서론
----

이 문서는 이더넷(10메가비트/초, 48비트 주소)에 적용된다. 실험적
이더넷(3메가비트/초, 8비트 주소)에서의 IP 데이터그램 전송 절차는
[3]에 기술되어 있다.


프레임 형식
-----------

IP 데이터그램은 표준 이더넷 프레임으로 전송된다. 이더넷 프레임의 타입
필드는 16진수 값 0800을 포함해야 한다. 데이터 필드는 IP 헤더 바로 뒤에
IP 데이터가 이어진다.

이더넷으로 전송되는 패킷의 데이터 필드 최소 길이는 46옥텟이다. 필요한
경우 이더넷 최소 프레임 크기를 충족하기 위해 데이터 필드를 (0 옥텟으로)
패딩해야 한다. 이 패딩은 IP 패킷의 일부가 아니며 IP 헤더의 전체 길이
필드에 포함되지 않는다.

이더넷으로 전송되는 패킷의 데이터 필드 최대 길이는 1500옥텟이므로,
이더넷으로 전송되는 IP 데이터그램의 최대 길이는 1500옥텟이다. 구현은
전체 길이 패킷을 지원하도록 권장된다. 게이트웨이 구현은 전체 길이
패킷을 수신하고 필요시 단편화할 준비가 되어 있어야 한다(MUST). 시스템이
전체 길이 패킷을 수신할 수 없다면, TCP 최대 세그먼트 크기 옵션 [4]
사용 등의 방법으로 다른 호스트가 보내지 않게 해야 한다.

참고: 이더넷의 데이터그램은 일반 인터넷 기본 최대 패킷 크기인
576옥텟보다 클 수 있다. 이더넷에 연결된 호스트는 같은 이더넷에 있지
않은 호스트에게 데이터그램을 보낼 때 이 점을 유념해야 한다. 중간
게이트웨이에서의 불필요한 단편화를 피하기 위해 더 작은 데이터그램을
보내는 것이 적절할 수 있다.


주소 매핑
---------

32비트 인터넷 주소에서 48비트 이더넷 주소로의 매핑은 여러 방법으로
수행할 수 있다.

**정적 테이블**

각 호스트에 로컬 네트워크의 다른 모든 호스트에 대해, 이더넷 주소와
인터넷 주소를 담은 테이블을 제공할 수 있다.

**동적 발견**

32비트 인터넷 주소와 48비트 이더넷 주소 간의 매핑은 주소 해석
프로토콜(ARP) [5]을 통해 수행할 수 있다. 인터넷 주소는 인터넷
네트워크에서 임의로 할당된다. 각 호스트의 구현은 자신의 인터넷 주소를
알아야 하고 이더넷 주소 해석 패킷에 적절히 응답해야 한다. 또한 필요할 때
인터넷 주소를 이더넷 주소로 변환하기 위해 ARP를 사용해야 한다.

**브로드캐스트 주소**

브로드캐스트 인터넷 주소(호스트 부분이 모두 이진수 1인 네트워크 주소)는
브로드캐스트 이더넷 주소(모두 이진수 1, FF-FF-FF-FF-FF-FF 16진수)로
매핑되어야 한다.

ARP 동적 발견 절차의 사용을 강력히 권장한다.


트레일러 형식
-------------

일부 Unix 4.2bsd 버전은 VAX 가상 메모리 아키텍처에서 네트워크
성능을 높이기 위해 다른 캡슐화 방법을 사용한다. 같은 이더넷의 합의된
시스템들은 서로 간에 이 형식을 사용할 수 있다.

어떤 호스트도 이를 구현할 필요는 없으며, 수신자가 해석할 수 있다고
확실히 알지 못하는 한 어떤 호스트에게도 이 형식의 데이터그램을
보내서는 안 된다. 트레일러 캡슐화의 세부사항은 [6]에 기술되어 있다.


바이트 순서
-----------

인터넷 프로토콜 명세 [1]의 부록 B에 설명된 대로, IP 데이터그램은
이더넷에서 8비트 바이트의 연속으로 전송된다.
