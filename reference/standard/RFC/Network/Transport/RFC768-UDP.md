# RFC 768 - 사용자 데이터그램 프로토콜(UDP)

```
RFC 768                                                        J. Postel
                                                                     ISI
                                                          1980년 8월 28일
```

## 1. 개요

RFC 768은 IP [1] 위에서 데이터그램을 교환하는 UDP를 정의한다. 애플리케이션이 최소한의 프로토콜 기능으로 다른 프로그램에 메시지를 보낼 수 있도록 하는 것이 목적이다. 트랜잭션 지향적인 방식으로, 전달이나 중복 방지는 보장하지 않는다. 순서가 보장되는 신뢰성 있는 데이터 스트림이 필요하면 TCP [2]를 사용한다.

## 2. 형식

```
                  0      7 8     15 16    23 24    31
                 +--------+--------+--------+--------+
                 |     Source      |   Destination   |
                 |      Port       |      Port       |
                 +--------+--------+--------+--------+
                 |                 |                 |
                 |     Length      |    Checksum     |
                 +--------+--------+--------+--------+
                 |
                 |          data octets ...
                 +---------------- ...

                      User Datagram Header Format
```

## 3. 필드

- Source Port
  - 선택적 필드 → 의미가 있는 경우 송신 프로세스의 포트를 나타냄
  - 다른 정보가 없을 때 응답이 보내져야 할 포트로 간주될 수 있음
  - 사용되지 않는 경우: 값 0 삽입
- Destination Port
  - 특정 인터넷 목적지 주소의 컨텍스트 내에서 의미를 가짐
- Length
  - 이 사용자 데이터그램의 헤더와 데이터를 포함한 옥텟 단위 길이
  - 최소값 8
- Checksum
  - IP 헤더로부터의 정보를 담은 의사 헤더 + UDP 헤더 + 데이터의 1의 보수 합에 대한 16비트 1의 보수
  - 2옥텟의 배수를 만들기 위해 필요한 경우 끝에 0 옥텟으로 패딩
  - 의사 헤더
    - UDP 헤더 앞에 개념적으로 붙음
    - 구성: 발신 주소, 목적지 주소, 프로토콜, UDP 길이
    - 잘못 라우팅된 데이터그램에 대한 보호 제공
    - 체크섬 절차: TCP에서 사용되는 것과 동일

```
                  0      7 8     15 16    23 24    31
                 +--------+--------+--------+--------+
                 |          source address           |
                 +--------+--------+--------+--------+
                 |        destination address        |
                 +--------+--------+--------+--------+
                 |  zero  |protocol|   UDP length    |
                 +--------+--------+--------+--------+
```

계산한 체크섬이 0이면 1의 보수 연산에서 같은 값인, 모든 비트가 1인 값으로 전송한다. 전송된 체크섬의 모든 비트가 0이면 송신자가 체크섬을 생성하지 않았다는 뜻이다. 디버깅할 때나 상위 프로토콜이 체크섬을 필요로 하지 않을 때 사용하는 표시다.

## 4. 사용자 인터페이스

사용자 인터페이스가 허용해야 하는 것:

- 새로운 수신 포트 생성
- 수신 포트에서의 수신 작업 → 데이터 옥텟과 발신 포트 및 발신 주소의 표시 반환
- 데이터그램을 보낼 수 있는 작업 → 보내야 할 데이터, 발신 및 목적지 포트와 주소 지정

## 5. IP 인터페이스

- UDP 모듈: 인터넷 헤더에서 발신 및 목적지 인터넷 주소와 프로토콜 필드를 결정할 수 있어야 함
- 가능한 UDP/IP 인터페이스 방식 중 하나: 수신 작업에 대한 응답으로 모든 인터넷 헤더를 포함한 전체 인터넷 데이터그램 반환
  - 이런 인터페이스는 UDP가 헤더 완비된 전체 인터넷 데이터그램을 IP에 전달해 보낼 수 있게 함
  - IP: 일관성을 위해 특정 필드를 검증하고 인터넷 헤더 체크섬 계산

## 6. 프로토콜 적용

- 주요 용도: 인터넷 네임 서버 [3], 간이 파일 전송 [4]

## 7. 프로토콜 번호

- 인터넷 프로토콜에서 사용될 때: 프로토콜 17(8진수 21)
- 다른 프로토콜 번호: [5]에 나열
